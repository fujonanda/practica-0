Preguntas:
1. ¿Qué significa programar de forma estructurada? 
Significa que el problema se divide en bloques de control o funciones que cumplen una función específica cada uno y que siguen un flujo secuencial, ordenado y fácil de leer y modificar, también implica hacer uso de estructuras de control para organizar la salida de las operaciones

2. ¿Cuáles son las tres estructuras fundamentales de control?
- Secuencia: Instrucciones que se ejecutan una después de otra
- Selección: Elegir entre varios caminos de acuerdo a las condiciones dadas (if, switch)
- Iteración: Repetir un bloque del programa una vez que este mismo termina (for, while, do-while)

3. ¿Qué ventaja tuvo separar el programa en funciones?
El código resulta bastante sencillo de comprender porque el orden en el que están descritas las funciones es el orden en el que se ejecutan en el programa, por lo tanto también fue fácil darle mantenimiento ante nuevas especificaciones o el surgimiento de casos inesperados ante los que el programa aún no estaba optimizado para responder. Tener funciones definidas desde el inicio tuvo la ventaja de no tener que repetir las mismas líneas de código varias veces a lo largo del archivo fuente

4. ¿Qué función tendría que modificarse si la calificación mínima aprobatoria cambiara?
Solo se tendría que cambiar la función estaAprobado modificando el número contenido dentro de las condiciones del if (ese número define cuál es la calificación mínima aprobatoria)

5. ¿Qué diferencia conceptual observa entre una función y un método?
Tanto una función como un método son bloques de código que reciben parámetros, realizan operaciones y producen un resultado de salida, la diferencia radica en que los métodos son parte de una clase u objeto

6. ¿Qué representa un commit en git?
Representa un punto de guardado donde se captura el estado del código en el momento en que se generó y queda como registro del avance del código

7. ¿Por qué es preferible usar varios commits pequeños en lugar de un solo commit al final?
Porque así es más fácil deshacer cambios o corregir errores en el código sin necesidad de comenzar desde cero, además que sirve para tener registro de qué cambio se realizó en un momento específico y por quién
